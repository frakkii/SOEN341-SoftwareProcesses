\# Team Process Definition



\## Workflow

We use Scrum. Tasks are tracked as GitHub Issues on a board: To Do → In Progress → In Review → Done. We meet at the start and end of each sprint.



\## Branching Strategy

\- `main` is the stable branch. No direct pushes.

\- Each task gets its own branch off `main`, e.g. `feature/login-page`.



\## Pull Request Process

\- Open a PR into `main` with a short description and a link to the issue.

\- Needs 1 teammate approval before merging.



\## Code Review Process

\- A teammate checks that the code works, is readable, and doesn't break anything.

\- The author fixes any comments before merging.



\## Definition of Ready

A story is ready when it has a clear description, acceptance criteria, and an estimate.



\## Definition of Done

A story is done when the code is reviewed, merged, works as expected, and the issue is closed.
